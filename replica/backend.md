## Decisiones

- **Tres clientes:**
  - Anónimo para las páginas públicas. RLS solo deja ver lo publicado aunque una consulta olvide el filtro.
  - Con la sesión del usuario para el panel y la cuenta. RLS aplica el rol en cada lectura y escritura.
  - Service role solo para tres cosas: votos, límites de uso y borrar cuentas.
- **Doble control en escrituras:**
  - `staffDb()` comprueba sesión y rol en código, para dar un mensaje claro.
  - RLS lo vuelve a comprobar en la base. Un redactor no puede publicar ni con una petición hecha a mano.
- **Concurrencia:** guardar compara `updated_at` dentro del mismo `UPDATE`, sin leer antes. Si otra persona guardó, no se actualiza ninguna fila y aparece el aviso "otra persona cambió esta nota".
- **Sin enumeración de cuentas:** entrar, registro y recuperar responden igual exista o no el correo.
- **Redirecciones seguras:**
  - `safeNext()` solo acepta rutas internas.
  - Los enlaces de email los valida Supabase contra su lista de URLs permitidas, así que una cabecera Host falsa no lleva a otro dominio.
- **Borrado del medio:** `sections.parent_id` y `articles.section_id` pasaron de `restrict` a `no action`.
  - Siguen impidiendo borrar una sección con notas.
  - El borrado en cascada desde `organizations` ahora funciona: `restrict` lo rompía.
- **`articles.number`:** pasó a `generated by default`, empezando en 100001, para que el seed conserve los números de sus URLs.

## Para conectar tu proyecto (lo haces tú)

1. Crea el proyecto en supabase.com (región cercana, por ejemplo `us-east-1`). Guarda la contraseña de la base en tu gestor de contraseñas.
2. Copia `web/.env.example` a `web/.env.local` y rellénalo:
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` y `SUPABASE_SERVICE_ROLE_KEY` salen de Project Settings → API.
   - `NOTICECAT_HASH_SALT` es una cadena aleatoria larga.
3. Aplica la migración desde `web/`:
   - `npx supabase login`
   - `npx supabase link --project-ref <ref>`: pide la contraseña de la base.
   - `npm run db:push`
4. En Authentication → URL Configuration:
   - Site URL: `http://localhost:3000`
   - Redirect URLs: `http://localhost:3000/auth/callback`
   - En producción, añade cada dominio de medio, por ejemplo `https://*.noticecat.app/auth/callback`.
5. En Authentication → Providers → Email:
   - Activa "Confirm email".
   - Contraseña mínima: 8 caracteres, con letras y números.
6. Carga los datos de prueba con `npm run db:seed -- --remoto`. Esto borra y recrea solo los dos medios de prueba y sus 3 usuarios.
7. Comprueba el acceso con `npm run db:test-rls`. Deben salir 17 "ok".
8. Reinicia `npm run dev`. La app pasa sola a Supabase.
